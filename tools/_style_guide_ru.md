# Стайлгайд перевода Orca на русский

Ты переводишь интерфейс **Orca** — десктоп-среды для работы с AI-агентами (IDE: рабочие пространства, worktree, терминалы, чаты с агентами, контроль исходников, GitHub/GitLab/Jira/Linear, настройки, мобильный компаньон).

Источник — **испанский** каталог Orca (машинный перевод с английского) или **английский** оригинал. Испанский местами кривой: если фраза выглядит бессмысленно, восстанови смысл по ключу (путь ключа = компонент/поле UI) и переводи по-русски естественно, а не калькой.

## Что сохранять дословно

- Плейсхолдеры: `{{count}}`, `{{value0}}`, `{{name}}`, `{prompt}` — **тот же набор, тот же текст**, порядок можно менять под русский порядок слов.
- Разметку: `<actor/>`, `<target/>`, `<b>…</b>`, `<link>…</link>`, `<agents>…</agents>` — теги и их вложенность сохраняются, переводится только текст внутри.
- Управляющие символы в начале/конце: `·`, `—`, `→`, `…`, двоеточия, кавычки-обёртки.
- Клавиши: `⌘`, `⇧`, `⌥`, `Ctrl`, `Alt`, `Shift`, `Esc`, `Tab`, `Enter`.

## Что не переводить (оставить как есть)

Бренды и продукты: Orca, GitHub, GitLab, Bitbucket, Jira, Linear, Slack, Discord, Notion, Figma, Sentry, Cursor, Claude, Codex, Gemini, Kimi, MiniMax, Grok, ZCode, Antigravity, OpenCode, Zed, VS Code, WSL, macOS, Windows, Linux, Android, iOS, Tailscale, Cloudflare.

Аббревиатуры и технические имена: API, CLI, URL, URI, SSH, PR, MR, JSON, YAML, TOML, CSV, PDF, HTML, CSS, SDK, MCP, OAuth, HTTP, DNS, CPU, RAM, Git, bash, zsh, fish, node, npm, pnpm, python, docker.

Исключение: `AI` переводится как **ИИ** (в пакете уже так: «настройки ИИ»).

## Стиль

- Кнопки, пункты меню, контекстные действия — инфинитив: «Открыть», «Удалить», «Добавить», «Скопировать», «Обновить», «Отмена».
- Описания, подсказки, ошибки — законченные предложения, обращение на «вы» со строчной: «Выберите…», «Если вы закроете…». Никакого «Вы» с заглавной и «пожалуйста».
- Orca — женского рода: «Orca не смогла…», «Orca остаётся установленной».
- Многоточие — один символ `…`, не три точки.
- Кавычки — «ёлочки»; тире — `—` с пробелами.
- Пунктуация в конце — как в источнике: у коротких подписей точки нет, у предложений есть.
- Без лишних пробелов по краям, без двойных пробелов, без `\n` (если их не было в источнике).
- Компактно: UI не резиновый, держись в пределах ~15 % от длины источника.
- Поисковые ключи (ключ содержит `.search.`, `keyword`, `keywords`) — строчными, без точки в конце, это токены поиска.
- Плюрализация ключами: `_one` → единственное число («1 файл»), `_other` и `_many` → родительный падеж множественного («5 файлов»).

## Когда возвращать пустую строку

Верни `""` (это значит «оставить английский оригинал»), если строка — литерал, а не текст интерфейса:

- команда/путь/URL: `orca://pair?code=...`, `git status`, `/path/to/destination`, `sk-...`;
- только бренд/аббревиатура/имя языка: `Beta`, `GraphQL API`, `Español`, `中文（简体）`, `Android APK`, `WSL ·`;
- только символы/единицы: `·`, `px`, `%`, `—`;
- код или CSS.

Не возвращай `""` для обычных подписей и предложений, даже коротких («Готово», «Нет» — переводим).

## Контекст и единообразие

- Путь ключа — лучший контекст: `auto.components.settings.TerminalPane.*` — настройки терминала, `components.native-chat.composer.*` — поле ввода в чате, `sidebar.agentSummary.*` — сводка агентов в боковой панели.
- Перед переводом незнакомого термина посмотри, как он уже переведён: `grep -F 'термин' tools/ru_overrides.json` или `grep -F '"settings.agents.' tools/ru_overrides.json`.
- Одинаковые исходные строки в одном батче переводи одинаково.

## Формат результата

Файл JSON строго такого вида:

```json
{"batch": 1, "items": [{"i": 0, "ru": "Перевод"}, {"i": 1, "ru": ""}]}
```

- Каждый `i` из входного файла — ровно один раз, без пропусков и дублей, без лишних полей.
- `ru` — строка; `""` только по правилу выше.
- После записи прогони валидатор и исправь всё, что он найдёт:

```sh
cd /Users/shutovks/projects/orca-russian/tools/_t246 && python3 check_batch.py batches/batchNN.json out/batchNN.json
```
